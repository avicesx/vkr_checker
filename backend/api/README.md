# API загрузки, статуса проверки и администрирования

API принимает ВКР в формате DOCX и методичку в формате DOCX или PDF. Размер
каждого файла ограничен 20 МиБ. Формат проверяется по расширению и содержимому;
заголовку `Content-Type` запроса API не доверяет.

## Запуск

Установите зависимости и задайте PostgreSQL URL, закрытый токен администратора,
каталог для документов и разрешенные origin-адреса фронтенда:

```sh
python -m pip install -r requirements.txt
export DATABASE_URL='postgresql+psycopg://user:password@localhost:5432/vkr_checker'
export ADMIN_TOKEN='replace-with-a-long-random-secret'
export CHECK_STORAGE_DIR=/path/to/persistent/check-files
export CORS_ALLOWED_ORIGINS='https://admin.example.org'
python -m uvicorn api.main:app --host 0.0.0.0 --port 8000
```

Для совместимости с Docker Compose также поддерживается переменная
`UPLOAD_STORAGE_DIR`; если заданы обе переменные, приоритет у `CHECK_STORAGE_DIR`.

Секрет `ADMIN_TOKEN` задается только в окружении backend и не должен попадать в
репозиторий или клиентскую сборку. При отсутствии токена административные
эндпоинты закрыты. Публичные эндпоинты загрузки и статуса токен не требуют.
В облаке API необходимо публиковать только через HTTPS reverse proxy. Файлы
хранятся в `CHECK_STORAGE_DIR/files/`, а статусы и административные данные —
в PostgreSQL.

При первом запуске `create_all()` создаёт отсутствующие таблицы. Изменения
существующей схемы автоматически не выполняются.

## Эндпоинты

`POST /api/v1/checks` принимает multipart-поля `thesis` (`.docx`) и
`guidelines` (`.docx` или `.pdf`). В ответе `201 Created` возвращаются UUID,
начальный статус `uploaded` и время создания в UTC.

`GET /api/v1/checks/{check_id}` возвращает текущий статус проверки или `404`,
если UUID неизвестен.

В перечислении статусов контракта OpenAPI также зарезервированы значения
`queued`, `processing`, `completed` и `failed` для будущего фонового обработчика.
Сейчас загрузка создаёт проверку со статусом `uploaded`; переходы между статусами
и поля результата или ошибки пока не реализованы.

### Администрирование

Все `/api/v1/admin/*` эндпоинты требуют заголовок
`Authorization: Bearer <ADMIN_TOKEN>`.

- `GET /api/v1/admin/org-units` — страничный список справочника; `POST`,
  `PATCH /{unit_id}` и `DELETE /{unit_id}` управляют университетами,
  институтами и кафедрами. Разрешены пропуски уровней, но не обратная иерархия.
- `GET /api/v1/admin/guidelines` — страничный список существующих методичек с
  фильтрами `search`, `year`, `org_unit_id`, `confirmed`.
- `GET /api/v1/admin/review-queue` — наборы, ожидающие проверки.
- `GET /api/v1/admin/rulesets/{id}` и
  `GET /api/v1/admin/rulesets/{id}/rules` — итоги и правила, отсортированные по
  возрастанию уверенности; ответ правила содержит цитату и ее место в документе.
- `PATCH /api/v1/admin/rules/{id}` — редактирование. Параметры проверяются
  схемой соответствующего типа правила. Изменение уже одобренного набора
  создает новую версию, не меняя родительскую.
- `POST /api/v1/admin/rules/{id}/decision` принимает `approved` или `rejected`;
  `POST /api/v1/admin/rulesets/{id}/approve-by-confidence` массово подтверждает
  правила не ниже заданного порога (без уверенности правила не выбираются).
- `POST /api/v1/admin/rulesets/{id}/activate` или `PATCH
  /api/v1/admin/rulesets/{id}/status` активирует полностью рассмотренный набор,
  если подтверждено хотя бы одно правило. Отклоненные правила не блокируют
  активацию; предыдущий активный набор архивируется в той же транзакции.
- `GET /api/v1/admin/analytics` возвращает статусы и динамику загрузок, долю
  ошибок, очередь проверки, статусы наборов, счетчики методичек и правил,
  частые нарушения и нарушения по организациям.

Параметры пагинации: `page` (с 1) и `page_size` (максимум 100). Ответ содержит
`items`, `total`, `page`, `page_size` и `pages`. Подтвержденные дословные цитаты
переиспользуются только при совпадении нормализованной цитаты, типа правила,
параметров и области действия; исходная строка правила сохраняется в наборе и
ссылается на ранее подтвержденное правило.

FastAPI публикует интерактивную документацию по адресу `/docs`, а схему OpenAPI —
по адресу `/openapi.json`. Файл `openapi.json` в репозитории проверяется на
соответствие схеме приложения. Обновляйте его при изменении эндпоинтов или
моделей.

Пересоздать файл из каталога `backend/` можно командой:

```bash
python -c 'import json; from pathlib import Path; from api.main import app; Path("openapi.json").write_text(json.dumps(app.openapi(), ensure_ascii=False, indent=2) + "\n", encoding="utf-8")'
```
