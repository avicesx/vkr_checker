# Отчёты о нарушениях

Функция `build_violation_report()` преобразует аномалии
`ParsedDocxDocument.anomalies` и результаты неуспешных проверок
`PdfRuleFinding` в единый сгруппированный отчёт. Успешные и неоценённые
PDF-правила не включаются. Неизвестные правила со статусом `fail` включаются с
общей категорией оформления и рекомендацией. Для каждого нарушения указываются
идентификатор, категория, критичность, доступное место, описание, рекомендация
и источник.

```python
from violation_reports import build_violation_report

report = build_violation_report(parsed_docx, pdf_report.findings)
json_for_result_page = report.model_dump(mode="json")
markdown_for_download = report.to_markdown()
```

Для места нарушения используются идентификаторы блоков парсера и, если они
доступны, оценочные номера страниц DOCX. Проверки оформления PDF относятся ко
всему документу, поэтому для них отдельная страница или блок не указываются.
Если DOCX не был выровнен по исходному PDF, номера страниц следует считать
оценочными.

Уровни критичности сейчас заданы как начальное соответствие в `report.py`.
Их нужно сверить с правилами нормоконтроля и реальными результатами Бэка №1.
Текущий API загрузки ещё не запускает анализ и не возвращает отчёты. Подключить
эту модель следует вместе с обработкой проверок и сохранением результата.
