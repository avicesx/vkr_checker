# Ссылки на источники: отчёт `citations.json`

Пакет находит в тексте документа внутритекстовые библиографические ссылки,
фиксирует их место и сопоставляет со списком литературы. Работает поверх
готового `ParsedDocument`, поэтому одинаково применим ко всем трём режимам
разбора (`docx_only`, `pdf_only`, `docx_pdf`) и не меняет парсер.

## Зачем отдельный пакет

Ссылки — производный артефакт: парсер отвечает за факты о документе (текст,
структура, список литературы), а ссылки считаются по этим фактам. Так отчёт
можно пересобрать из `parse.json` без повторного разбора и без LibreOffice и
PyMuPDF. Сканер при этом написан как самостоятельный модуль, чтобы позже стать
общим слоем обогащения документа (см. «Ограничения и дальнейшая работа»).

## Формы ссылок

| Форма | Пример | `style` | `targets` |
|---|---|---|---|
| Числовая | `[3]` | `numeric` | `["3"]` |
| Числовая со страницей | `[3, с. 15]` | `numeric_with_page` | `["3"]`, `page_in_source="15"` |
| Диапазон | `[1–4]` | `numeric_range` | `["1","2","3","4"]` |
| Диапазон с перечислением | `[3, 5-7]` | `numeric_range` | `["3","5","6","7"]` |
| Автор-год | `(Иванов, 2020)` | `author_year` | `["Иванов, 2020"]` |
| Автор-год с «и др.» | `(Иванов и др., 2020, с. 15)` | `author_year` | `["Иванов, 2020"]` |

Страница источника (`, с. 15`, `, стр. 15-17`, `, p. 15`) не становится целью:
она попадает в `page_in_source`. Диапазон длиннее 50 номеров считается
опечаткой и раскрывается только по краям.

## Контракт отчёта

```json
{
  "schema_version": "1.0.0",
  "source": {"filename": "vkr.docx", "sha256": "…", "parse_mode": "docx_only", "page_count": 87},
  "citations": [{
    "citation_id": "cit_0001",
    "raw": "[3, с. 15]",
    "style": "numeric_with_page",
    "targets": ["3"],
    "page_in_source": "15",
    "authors": [],
    "year": null,
    "resolved_bib_ids": ["bib_003"],
    "resolution": "resolved",
    "block_id": "p_00412",
    "page_est": 12,
    "start_char": 148,
    "end_char": 157,
    "section": "1.2 Анализ предметной области",
    "context": "…согласно данным [3, с. 15], можно…"
  }],
  "summary": {
    "total": 65,
    "by_style": {"numeric": 65},
    "resolved": 65,
    "unresolved": 0,
    "unique_sources": 26
  },
  "not_extracted": []
}
```

`start_char`/`end_char` — смещения в `text_visible` абзаца, `page_est` — оценка
страницы абзаца, `section` — ближайший предшествующий заголовок по
`document_tree`, `context` — окно ±60 символов для ручной проверки.

## Сопоставление со списком литературы

- **Числовые ссылки** сопоставляются по `order_index` записи
  `cross_ref_index.bibliography`: `[3]` → запись №3.
- **Автор-годовые** — по фамилии и году: фамилия должна встречаться в
  `raw_text` записи (без учёта регистра), год — как подстрока.
- Если совпадений нет или список литературы не извлечён, ссылка получает
  `resolution="unresolved"`, а причина попадает в `not_extracted`.

## Что не сканируется

- **Раздел литературы** — исключается по `document_tree`
  (`semantic_role="bibliography"`), иначе записи списка считались бы ссылками в
  тексте. Механизм общий для DOCX и PDF.
- **Таблицы** — в v1 не сканируются: `ParagraphBlock` в ячейках не обходится.
- **Колонтитулы, сноски, надписи** — сканируется только `container_type="body"`.

## Запуск

```powershell
# из backend
python manual_test/extract_citations.py manual_test/3.docx --out out/3.citations.json
python manual_test/extract_citations.py manual_test/3.pdf --mode pdf_only --out out/3.pdf.citations.json
python manual_test/extract_citations.py out/parse.json --out out/citations.json
```

Из кода:

```python
from citations import extract_citations
from services.references import extract_citations_to_json_file

report = extract_citations(document)                    # ParsedDocument -> CitationReport
report = extract_citations_to_json_file("parse.json", "citations.json")
```

## Проверка на реальных документах

| Документ | Ссылок | Сопоставлено | Замечание |
|---|---|---|---|
| `2_Бутаков…docx` | 65 | 65 (26 источников) | — |
| `3.docx` | 1 | 1 (`bib_034`) | записи списка литературы в отчёт не попали |
| `3.pdf` | 1 | 0 | `pdf_only`: записи списка не извлекаются, ссылка `unresolved` |

## Ограничения и дальнейшая работа

- **Автор-год в одной скобке с несколькими источниками** —
  `(Иванов, 2020; Петров, 2021)` — распознаётся только первая запись.
- **Границы списка литературы** в DOCX местами неточные (парсер захватывает
  соседний текст): на `3.docx` это давало 134 мусорные записи. На извлечение
  ссылок не влияет (раздел исключается по дереву), но влияет на сопоставление.
- **Унификация DOCX/PDF**: цитаты, библиография и подписи — текстовые
  паттерны, не зависящие от формата. Следующий шаг — общий слой обогащения
  `ParsedDocument`, который для PDF заполнит `cross_ref_index` и сделает
  `capabilities.cross_references=True` честным; этот пакет — его первый кусок.
- **Формулы и сноски в PDF** не извлекаются и в эту задачу не входят.

## Тесты

`tests/test_citations.py` — формы ссылок, место в документе, исключение раздела
литературы, сопоставление, честные пометки, round-trip отчёта и сервис
`parse.json → citations.json`. Документы собираются синтетически, бинарные
образцы не нужны.
