**Срез:** `727ce12 docs: record neutral base defaults` (ветка `feat/urgpu-ruleset`), дерево чистое, кроме чужих неотслеживаемых файлов.
**Базовая линия:** `4edc509` (ветка `chore/alembic-and-regression-tests`, дефолтный набор 3.0.0).
**Промежуточный срез:** `3d196d9` (до t28, база 4.0.0 на 53 правила) — используется только для объяснения дельты.
**Корпус:** пять реальных ВКР из `backend/manual_test/`: Бикчуркина (docx, 804 блока), Бутаков (docx, 788), `3.docx` (docx, 672), Смолина (pdf, 375), Мартемьянова (pdf, 522).

## 1. Методика

1. Базовая линия поднята отдельным worktree `C:/code/vkr_baseline_t26` на `4edc509`, чтобы не трогать общий worktree команды. Скрипты замера лежат в `backend/manual_test/_t26_*.py` (каталог в `.gitignore`).
2. Для каждого документа выполнен полный путь `parse → engine → report` в трёх конфигурациях: дефолтный набор, профиль УрГПУ, а также профили МПГУ и УрФУ на финальном срезе. Сохранены все `violations`, markdown-отчёт, счётчики по кодам и правилам: `backend/manual_test/_t26_baseline.json`, `_t26_current.json`, `_t26_after.json`.
3. Паритет проверялся по 37 `rule_id` набора 3.0.0: для каждого документа сравнивались счётчики каждого старого правила, а не только сумма.
4. Адреса проверялись программно: у каждой находки проверялись `block_id`, `page_start`/`page_end`, `section_idx`; отдельно измерялась доля находок без адреса.
5. Точность новых правил оценена двумя способами: сплошная классификация всех 652 находок новых правил по типу записи (печатная книга / электронный ресурс / нормативный акт) и ручной разбор случайной выборки из 20 находок (`seed=20261125`, `backend/manual_test/_t26_after_random20.txt`) с проверкой блока, страницы и текста.
6. Профиль УрГПУ проверен на синтетическом повреждённом docx (`backend/manual_test/_t26_synthetic.py`): поля 15/20/20 мм, тело Times New Roman 14 полужирным, заголовки строчными, `page_break_before` у заголовков и подраздела, колонтитул с полем PAGE.
7. Тесты: `cd backend; export DATABASE_URL='postgresql+psycopg://vkr_checker:local-dev-password@localhost:5433/vkr_checker_test'; export TEST_DATABASE_URL="$DATABASE_URL"; python -m pytest tests/ -q` → **1148 passed, 8 skipped, 1 warning** (48.68 s, exit 0), включая чужой неотслеживаемый `backend/tests/test_contract_doc.py`; без него на этом же коде — 1127 passed, 8 skipped (40.69 s). Чистое дерево без корпуса: 993 passed, 43 skipped.

## 4. Адреса находок

Требование «у каждой находки есть `block_id` и страница» **не выполнено на 100%**: в базовом прогоне 11 из 1712 находок (0,64%) без полного адреса, в профиле УрГПУ — 22 из 2527 (0,9%).

| Документ | База: без block_id | База: без страницы | УрГПУ: без block_id | УрГПУ: без страницы |
|---|---:|---:|---:|---:|
| Бикчуркина | 0 | 1 (`bibliography_count`) | 1 (`page_margins`) | 1 |
| Бутаков | 0 | 0 | 3 (`page_margins`) | 1 |
| 3.docx | 0 | 1 (`bibliography_recency`) | 1 (`page_margins`) | 1 |
| Смолина | 4 (`page_margins`, `page_format`, `document_volume` ×2) | 3 (`document_volume` ×2, `bibliography_count`) | 6 | 3 |
| Мартемьянова | 2 (`page_margins` ×2) | 0 | 4 | 1 |

Что здесь допустимо, а что дефект:

* `page_margins` и `page_format` — правила уровня секции: у них нет абзаца, но есть `section_idx` и диапазон страниц (например, `page_margins:section:0`, страницы 1–52 у Смолиной). Это корректный адрес, а не «находка в воздухе».
* `document_volume` — **дефект D4**: `backend/rule_engine/checks/common.py:596-600` строит локацию только с `snippet="структура документа"`, без `block_id` и без страницы. Две находки на каждый pdf-прогон.
* `bibliography_count` и `bibliography_recency` — **дефект D5**: `_bibliography_summary_location` (`backend/rule_engine/checks/bibliography.py:530-536`) берёт `block_id` первой записи, но не заполняет страницы.
* `title_page_content_default` — **дефект D10**: на `3.docx` (титульного листа нет) все 9 находок привязаны к `p_00001` с текстом «Содержание:». По сути замечание верное, но адрес и сниппет вводят в заблуждение.

## 7. Читаемость отчёта

Структура отчёта: заголовок «Отчёт о нарушениях: <файл>», затем `##`-разделы по семействам («Оформление», «Целостность документа», «Рисунки и иллюстрации», «Структура документа», «Список литературы и ссылки на источники», «Подписи рисунков и таблиц»), внутри — `###` по правилу с числом замечаний и примерами адресов. Аномалии парсера перечисляются отдельными записями `### [LOW] empty-paragraphs:…`.

| Метрика | База 3.0.0 | База 4.0.0 | УрГПУ 2.0.0 |
|---|---:|---:|---:|
| Строк (Бикчуркина / Бутаков / 3.docx / Смолина / Мартемьянова) | 830 / 1464 / 541 / 42 / 66 | 852 / 1483 / 576 / 79 / 92 | 907 / 1524 / 583 / 128 / 168 |
| Средняя длина строки | 45,4 / 44,6 / 53,7 / 69,1 / 69,1 | 49,0 / 46,3 / 58,8 / 84,0 / 89,1 | 54,7 / 48,6 / 64,7 / 110,8 / 107,9 |
| Строк длиннее 500 символов | 3 / 4 / 2 / 1 / 1 | 5 / 6 / 4 / 2 / 3 | 10 / 10 / 10 / 8 / 9 |
| Максимальная строка | 824 / 1083 / 1072 / 642 / 643 | 1089 / 1092 / 1092 / 1092 / 1092 | 1088 / 1091 / 1092 / 1113 / 1132 |

Счётчики в заголовках групп есть, примеры ограничены 10 адресами и снабжены «и ещё N». Проблема — эти 10 адресов склеены в одну строку до 1092 символов, а сниппеты обрезаются на 80 символах посередине слова («тенден…»). Для чтения в браузере и печати это плохо (дефект D12).

## 9. Ограничения

* **PDF.** Смолина и Мартемьянова парсятся как `pdf_only`; находки ограничены текстовым слоем, номера страниц — страницы PDF. Сканы и картинки не анализируются, поэтому часть правил оформления к ним неприменима.
* **Разметка DOCX.** Страницы для docx оцениваются эвристикой (разрывы, объём), а не движком Word; `page_start` — оценка, что видно по совпадению страниц у соседних блоков.
* **Корпус.** Пять ВКР, из них только три docx; `3.docx` без титульного листа, поэтому дефект D10 на нём гипертрофирован. Эталонной разметки нет, «ложность» определялась вручную по методичке и тексту записи.
* **Выборка.** 20 находок дают широкий интервал; сплошная оценка точности (62,1%) опирается на классификацию типов записей, а не на построчную проверку всех 652 находок.
* **Аномалии парсера** (154/285/88) не относятся к rule_engine и в оценку точности правил не входят.
* **Синтетика** проверяет только четыре правила профиля (шрифт, поля, регистр заголовков, перенос подраздела), а не весь набор.
* Профильные значения взяты из методички УрГПУ; для МПГУ и УрФУ сверялись только числа и переопределения, без содержательной экспертизы их требований.
