# Спецификация проверок по методичке УрГПУ

Источник: `вкр_3_работы.xlsx`, лист пула требований, отобраны только строки с «Файл» = `ургпу.doc` — **67 требований** (в исходном пуле 329 строк по трём методичкам). Цитаты приведены дословно, в том виде, в котором они лежат в пуле (колонка «Дословная формулировка»).

Разбор: каждая цитата сверена с (а) набором кодов правил `backend/rule_engine/rules/vkr_test_rules.json` (27 уникальных `code`, ruleset `vkr-rule-engine-test` 3.0.0) и их pydantic-моделями в `backend/rule_engine/rules.py`, (б) схемой распарсенного документа `backend/parser/core/schema.py`, (в) фактическим наличием данных в двух реальных ВКР (`backend/manual_test/out/2.json` — 409 блоков, `backend/manual_test/out/3.json` — 672 блока).

Статусы:

| статус | значение |
| --- | --- |
| реализуемо сейчас | код правила и нужные ему параметры уже есть, данные в JSON заполнены |
| нужен новый параметр | код правила есть, но его модель/проверка не выражает требование: нужен новый ключ `params` |
| нужен новый код | правила для такого требования нет вовсе (рядом приведено предлагаемое имя) |
| нужен парсер | без новых данных от разбора документа требование не проверить |
| непроверяемо движком | нужен смысл текста или внешний сервис, детерминированная проверка невозможна |
